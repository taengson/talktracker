# TalkTracker 개발 계획서

## 1. 프로젝트 개요

TalkTracker는 로컬 음성 파일에서 **누가, 언제, 무엇을 말했는지**를 정리하는 개인용 화자 분리·전사 도구다. 음성은 사용자의 컴퓨터에서 처리하며, 결과는 화자별 대본과 자막 파일로 저장한다.

### 목표

- 회의, 인터뷰, 통화 녹음 등의 로컬 파일을 화자별로 전사한다.
- 한국어를 우선으로 하되 다국어 음성도 처리한다.
- 화자 구간과 전사문을 시간 기준으로 결합한다.
- 결과를 화면에서 읽고, Markdown과 인쇄하기 좋은 HTML 문서로 저장한다.
- 모델을 한 번 내려받은 뒤에는 인터넷 연결 없이 실행할 수 있게 한다.

### 이번 범위에서 제외할 것

- 실시간 마이크 전사
- 실제 인물 이름을 자동 식별하는 음성 인식/화자 인증
- 클라우드 업로드·계정·공유 기능
- 모바일 앱

## 2. 핵심 기술 선택

| 역할 | 선택 | 이유 |
| --- | --- | --- |
| 음성 전사 | `openai/whisper-large-v3-turbo` + faster-whisper CPU `int8` | Turbo의 다국어 품질을 유지하면서 CPU 전사 속도와 메모리 사용량을 낮춘다. |
| 화자 분리 | `nvidia/Nemotron-3-Diarization` | 최대 8명의 화자 구간, 오프라인 처리, 동시 발화 구분을 지원한다. |
| 실행 환경 | Python | 두 모델의 공식 라이브러리 생태계와 가장 잘 맞는다. |
| 사용자 화면 | Python 데스크톱 UI (Tkinter) | 브라우저 없이 파일 선택, 진행 상태, 결과 편집과 내보내기를 단순하게 제공한다. |
| 오디오 정규화 | FFmpeg | 다양한 입력 형식을 16 kHz 모노 WAV로 일관되게 준비한다. |

> Nemotron은 화자 이름 대신 `화자 1`, `화자 2`처럼 익명 화자 라벨을 제공한다. 사용자는 결과 화면에서 라벨을 원하는 이름으로 바꿀 수 있다.

## 3. 처리 흐름

```text
음성 파일 선택
  → 오디오 검사 및 16 kHz 모노 변환
  ├→ Nemotron: 화자별 발화 구간 생성
  └→ Whisper Turbo: 전사문 및 단어별 시간 정보 생성
  → 시간 축 기준으로 화자 구간과 단어를 결합
  → 짧은 구간 병합·무음 정리·동시 발화 표시
  → 결과 검토 및 Markdown / HTML 문서 저장
```

### 결과 데이터의 기본 형태

```json
{
  "start": 72.4,
  "end": 76.2,
  "speaker": "화자 1",
  "text": "다음 안건으로 넘어가겠습니다.",
  "overlap": false
}
```

동시 발화가 감지된 구간은 두 화자 라벨을 함께 보존한다. 화자 하나로 억지로 합치지 않는다.

## 4. 개발 단계

### 단계 0 — 환경 검증

목적: 현재 PC에서 두 모델을 실제로 불러오고, 1~5분 길이의 샘플 파일을 끝까지 처리할 수 있는지 확인한다.

작업:

- Windows, Python, FFmpeg, PyTorch 및 GPU/CPU 상태 확인
- Hugging Face 접근 토큰으로 Nemotron 모델 다운로드 확인
- Whisper Turbo와 Nemotron의 단독 실행 확인
- CPU 전용과 NVIDIA GPU 환경에서 처리 시간·메모리 기록

완료 기준:

- 로컬 WAV 파일 하나에서 전사와 화자 구간이 모두 생성된다.
- 발생한 설치·호환성 이슈와 해결 방법이 문서화된다.

### 단계 1 — 처리 엔진 프로토타입

목적: 명령 한 번으로 음성 파일에서 화자별 대화 기록을 만든다.

작업:

- 입력 파일 유효성 검사 및 오디오 변환
- Whisper Turbo의 문장/단어별 타임스탬프 추출
- Nemotron의 화자 구간 추출
- 시간 겹침 비율을 기준으로 단어·문장을 화자에게 배정
- 구간 병합과 동시 발화 처리
- 처리 오류와 모델 다운로드 상태를 알기 쉬운 메시지로 반환

완료 기준:

- 단일 파일을 처리해 화자, 시작·종료 시각, 전사문을 가진 내부 대화 기록이 생성된다.
- 화자가 바뀌는 짧은 테스트 음성에서 화자별 문장이 분리된다.

### 단계 2 — 읽기 좋은 결과 문서 만들기

목적: 생성 결과를 바로 읽고 보관할 수 있는 문서로 만든다.

작업:

- Markdown: 메모 앱이나 문서 도구에서 계속 편집할 수 있는 대화 기록
- HTML: 브라우저에서 편하게 읽고 인쇄 또는 PDF로 보관할 수 있는 문서
- 원본 파일명, 처리 모델, 생성 시각 등의 메타데이터 기록

완료 기준:

- 두 문서 모두에서 시간순·화자 라벨·본문이 일관된다.

### 단계 3 — 로컬 사용자 화면

목적: 터미널 없이 파일을 선택하고 결과를 검토한다.

작업:

- 드래그 앤 드롭 또는 파일 선택
- 처리 단계와 진행 상태 표시
- 화자별 대본 보기 및 시간 클릭 시 해당 위치 표시
- `화자 1` 등의 라벨을 사용자가 이름으로 변경
- Markdown 문서 저장, HTML 문서 열기, 인쇄 또는 PDF 저장
- 사용자는 모델·CPU/GPU 설정을 고르지 않는다. 앱이 로컬 환경에 맞는 기본 설정을 사용한다.

완료 기준:

- 처음 쓰는 사용자도 파일 하나를 넣어 결과를 저장할 수 있다.

### 단계 4 — 품질 및 성능 보완

목적: 실제 회의·인터뷰 파일에서 신뢰할 수 있는 결과를 만든다.

작업:

- 한국어 회의, 2인 인터뷰, 다인 대화, 잡음·겹침 발화 샘플로 검증
- 화자 전환 직후의 잘린 문장과 짧은 오분류 구간 보정
- Whisper Turbo와 large-v3의 품질·처리 시간 비교
- CPU 실행 시 모델 로딩·변환·추론 단계별 시간 기록
- 처리 실패 시 중간 결과 보존과 재시도 지원

완료 기준:

- 대표 샘플별 알려진 한계와 권장 설정을 사용자 문서에 명시한다.

## 5. 화자-전사 결합 규칙

1. Whisper 단어 또는 문장마다 시작·종료 시간을 읽는다.
2. 같은 시간대의 Nemotron 화자 구간을 찾는다.
3. 겹치는 시간이 가장 긴 화자를 기본 화자로 지정한다.
4. 충분한 길이로 두 화자가 겹치면 두 화자 라벨과 `overlap: true`를 기록한다.
5. 인접한 같은 화자의 짧은 조각은 문장 흐름을 해치지 않는 범위에서 병합한다.
6. 어떤 화자 구간에도 속하지 않는 전사문은 `알 수 없음`으로 남긴다.

## 6. 주요 위험과 대응

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| Windows에서 Nemotron 의존성 호환 문제 | 설치 또는 실행 실패 | 단계 0에서 실제 환경 검증을 먼저 수행하고, Python/Transformers 경로를 우선 사용한다. |
| GPU가 없거나 VRAM이 부족함 | 긴 파일 처리 시간이 길어짐 | CPU 모드를 제공하고, 기본 모델을 Turbo로 유지하며, 필요하면 `medium`을 선택지로 둔다. |
| 동시 발화·잡음 | 화자 배정 오류 | 겹침을 보존하고, 결과 화면에서 라벨과 문장을 편집할 수 있게 한다. |
| 화자 번호가 파일마다 달라짐 | 이름 연속성 혼란 | 파일별 익명 라벨을 기본으로 하고 사용자가 이름을 붙이게 한다. |
| 긴 파일의 메모리·처리 실패 | 결과 유실 | 청크 처리, 단계별 임시 결과 저장, 오류 후 재시도 기능을 둔다. |

## 7. 초기 디렉터리 구상

```text
talktracker/
├─ src/talktracker/      # Python 데스크톱 화면과 향후 전사·화자 분리 로직
├─ docs/                 # 계획서, 설치·사용 문서
├─ models/               # 프로젝트 전용 로컬 모델 파일 (Git 제외)
├─ scripts/              # Windows 패키지 준비·모델 다운로드 진입점
├─ outputs/              # 사용자가 저장한 결과 (Git 제외)
└─ requirements.txt      # Python 실행 의존성
```

## 8. 완료 정의 (MVP)

다음 흐름이 인터넷 연결 없이 재현되면 MVP를 완료로 본다.

1. 사용자가 지원되는 로컬 음성 파일을 선택한다.
2. TalkTracker가 익명 화자 라벨과 시간 정보가 포함된 전사 결과를 생성한다.
3. 사용자가 화자 이름을 수정한다.
4. 사용자가 Markdown 또는 HTML 문서로 결과를 저장한다.

## 9. 시작 전 결정할 항목

- 지원할 첫 입력 형식 범위: WAV/MP3 우선 또는 M4A/MP4까지 포함
- CPU 환경에서 허용할 최대 처리 시간
- 결과 편집 기능을 MVP에 포함할지, 읽기·내보내기만 먼저 만들지
